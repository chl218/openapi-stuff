Contract-first: the YAML comes first

Flip the direction. Agree on the contract, then generate a typed C# client and server stubs from it. The code has to fit the contract, not the other way round.

What you will learn

  • Author library.yaml by hand, using $ref and reusable responses.
  • Generate server stubs and a C# client from it with NSwag (Kiota is a Microsoft alternative).
  • Implement the generated abstract members against an in-memory store.
  • Write one test that calls the real server through the generated client.

When to choose it

Pick contract-first when another team, a mobile app, or an outside customer will build against the API before your code exists. The YAML becomes the thing you review and approve. Pick code-first for a small internal service where speed matters more.

Run it locally Use the spec you wrote in Lesson 1 and grow it. Make two projects: Library.Server and Library.Client.Tests. Generate code at build time so it is never edited by hand. The pseudocode lists the steps; choose NSwag or Kiota and read its current docs for exact commands.
You are done when Changing a field name in the YAML breaks compilation of both the server and the test project. That break is the feature.
