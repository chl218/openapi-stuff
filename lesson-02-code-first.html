Code-first: let ASP.NET Core write the spec

You write minimal API endpoints. The framework inspects them at startup and serves an OpenAPI document. Swagger UI reads that document and draws a page you can click.

What you will learn

  • Create a minimal API project with dotnet new web.
  • Turn on OpenAPI generation (the built-in Microsoft.AspNetCore.OpenApi package) and fetch the JSON.
  • Add a Swagger UI front end (Swashbuckle.AspNetCore.SwaggerUI) pointed at that JSON.
  • Use typed results so the spec shows real response bodies.

Workflow

  1. Create the project and an in-memory Book list (no database yet).
  2. Map GET /books, GET /books/{id}, POST /books, DELETE /books/{id}.
  3. Register OpenAPI and map the document endpoint.
  4. Add the Swagger UI middleware, development only.
  5. Run, open the UI, call each endpoint from the page.
Why two packages? Since .NET 9 the template no longer bundles Swashbuckle. The built-in package generates the document. Swagger UI (or an alternative such as Scalar) is only a viewer. You can use the document without any UI.
Run it locally dotnet new web -n LibraryApi, implement per the pseudocode, then dotnet run. Open the URL shown in the console and add /openapi/v1.json, then /swagger. Save the JSON; you will diff it in Lessons 6–7.
You are done when Swagger UI lists four operations and "Try it out" creates a book that a later GET returns. The JSON shows a Book schema under components.
