One file describes your API. Everything else is generated from it.

OpenAPI is a machine-readable contract for an HTTP API. Swagger is the tooling built around it. This course takes you from reading a contract to deploying an API that publishes one, in C# on ASP.NET Core.

The big picture

Solid arrow: the server produces the contract. Dashed arrow: you write the contract first and the server must match it.

The workflow you will practise

Evolving the API sends you back to Design. The loop never stops.

Start here: two crash courses

New to YAML or to ASP.NET Core? Do these first. If you already write both, skip to Lesson 1.

  • A. YAML crash courseIndentation, quoting traps, multi-line strings, and the YAML you meet in specs.
  • B. ASP.NET Core serverBuilder, DI, configuration, middleware, routing, and results.

Learning plan

Eight lessons, each about 60–90 minutes. Every lesson has a page with a diagram and a folder of pseudocode. You write the real C#.

  • 1. Anatomy of a contractRead and hand-write an OpenAPI document.
  • 2. Code-first in ASP.NET CoreGenerate the spec from a running API. Open Swagger UI.
  • 3. Describe it wellSchemas, status codes, examples, validation rules.
  • 4. Contract-firstWrite the YAML, then generate a client and server stubs.
  • 5. Security schemesDocument and enforce JWT bearer auth.
  • 6. Versioning and breaking changesEvolve the API without breaking consumers.
  • 7. Build pipelineEmit, lint, diff, and test the spec in CI.
  • 8. DeployContainer, CI/CD, and publishing docs safely.

Code-first or contract-first?

Code-firstContract-first
You writeC# endpoints; the spec is generatedYAML spec; C# is built to match
Good whenOne team owns server and clients; you want speedSeveral teams or external consumers; the API is the product
RiskA refactor can silently change the contractSpec and code can drift unless you test for it

Run everything locally

  • Open any .html lesson by double-clicking it. No server needed.
  • Install the .NET SDK (the course targets .NET 10, the current LTS; .NET 9 also works). Check with dotnet --version.
  • Later lessons use two optional tools: npm (for Spectral lint) and Docker (for Lesson 8). Each lesson says when.
How the pseudocode folders work Each lesson has pseudocode/lesson-NN-…/ with a README.md (goal, run steps, done-checks) and .pseudo files describing what to build. They contain no C#. Create a fresh project next to them and translate the steps yourself.
Solutions After you try a lesson, compare your work with solutions/. It mirrors pseudocode/ with working C#, YAML, and scripts. It was written without a compiler, so read solutions/README.md for what may need small fixes.

Package names and versions change. Check NuGet for the current release before you add one.
