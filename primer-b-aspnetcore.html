An ASP.NET Core server, line by line

Lessons 2 to 8 all start from a Program.cs like the one below. This primer explains what each line does: the builder, services, configuration, middleware, endpoints, and how a request flows through them. No OpenAPI yet.

Top: the per-request path. Bottom left: what the builder sets up once. The dashed blue arrow is dependency injection handing services to the handler.

What you will learn

  • The five phases of Program.cs: builder, build, middleware, endpoints, run.
  • Dependency injection and the three service lifetimes.
  • Configuration layering, environments, and launchSettings.json.
  • How routing and parameter binding decide where each handler argument comes from.
  • Returning results and errors the way the rest of the course does (TypedResults, Problem Details).

1. The smallest server

dotnet new web -n HelloApi
cd HelloApi
dotnet run
var builder = WebApplication.CreateBuilder(args);   // 1. config, logging, services
var app = builder.Build();                          // 2. the app
app.MapGet("/", () => "Hello World!");              // 4. an endpoint
app.Run();                                          // 5. start listening

Microsoft.NET.Sdk.Web in the .csproj pulls in the whole framework: the Kestrel web server, routing, JSON, logging. Minimal APIs (MapGet and friends) are the style this course uses. Controllers are the older class-based style; Lesson 4 generates one.

3. Services and dependency injection

Register a class once with the builder. Any handler that lists it as a parameter receives an instance. You never call new on it yourself.

builder.Services.AddSingleton<ShelfStore>();   // one instance, shared by every request
builder.Services.AddScoped<RequestStamp>();    // a fresh one per HTTP request

app.MapGet("/shelf", (ShelfStore store) => store.All());   // injected by type
LifetimeOne instance perTypical use
Singletonappin-memory caches and stores (must be thread-safe), HTTP clients
Scopedrequestdatabase contexts, per-request state
Transientinjectionsmall stateless helpers
Requests run in parallel A singleton is shared by every request at once. If it holds a List<T> you change, guard it with a lock or use a concurrent collection. The course's in-memory book stores do this.

4. Configuration and environments

Configuration is a set of layered key/value sources. Later sources win:

appsettings.json  →  appsettings.{Environment}.json  →  user secrets (Development)
                  →  environment variables  →  command-line arguments
// appsettings.json
{ "Library": { "Name": "Primer Library", "Greeting": "Welcome." } }

// read one value
app.MapGet("/", (IConfiguration config) => config["Library:Greeting"]);

// or bind a whole section to a class
builder.Services.Configure<LibraryOptions>(builder.Configuration.GetSection("Library"));
app.MapGet("/name", (IOptions<LibraryOptions> o) => o.Value.Name);

Nested keys use : in code and __ (double underscore) in environment variables: Library__Greeting=hi. The environment comes from ASPNETCORE_ENVIRONMENT, or dotnet run --environment Production. Check it with app.Environment.IsDevelopment(); Lessons 2 and 8 use this to show Swagger UI only in Development.

5. Middleware: the request pipeline

Middleware is code every request passes through, in the order you add it. Each piece can act before and after the rest of the pipeline, or stop the request early.

app.UseExceptionHandler();   // outermost: catches exceptions from everything below
app.UseStatusCodePages();    // gives empty 404s a body

app.Use(async (context, next) =>
{
    var watch = Stopwatch.StartNew();
    // ... before: runs on the way in
    await next(context);     // the rest of the pipeline, then the endpoint
    // ... after: runs on the way out
    app.Logger.LogInformation("{Path} took {Ms} ms", context.Request.Path, watch.ElapsedMilliseconds);
});

Order matters. Exception handling goes first so it wraps everything. Authentication goes before authorization (Lesson 5). The Map… calls can sit anywhere in Program.cs: endpoints always run at the end of the pipeline, after every middleware.

6. Routing and parameter binding

app.MapGet("/hello/{name}", (string name, bool? shout) => ...);   // /hello/Ada?shout=true
app.MapGet("/shelf/{id:int}", (int id) => ...);                    // :int constraint; /shelf/abc → 404
app.MapPost("/shelf", (NewBook input) => ...);                    // JSON body
app.MapDelete("/shelf/{id:int}", ...);

var shelf = app.MapGroup("/shelf");                               // shared prefix
shelf.MapGet("/", ...);                                           // → GET /shelf

ASP.NET Core decides where each handler argument comes from:

ParameterComes fromOverride with
Name matches a {segment} in the routeroute[FromRoute]
Type registered as a serviceDI container[FromServices]
Simple type (int, string, bool…) not in the routequery string[FromQuery]
Complex type (record, class)JSON body[FromBody]
Anythingheader[FromHeader(Name = "User-Agent")]
HttpContext, CancellationTokenthe current request—

Nullable or defaulted parameters (bool? shout, int max = 50) are optional. Others are required, and a missing one gives a 400.

7. Results and errors

app.MapGet("/shelf/{id:int}", Results<Ok<Book>, NotFound> (int id, ShelfStore store) =>
    store.Find(id) is { } book ? TypedResults.Ok(book) : TypedResults.NotFound());

app.MapPost("/shelf", (NewBook input, ShelfStore store) =>
{
    var book = store.Add(input);
    return TypedResults.Created($"/shelf/{book.Id}", book);   // 201 + Location header
});
  • Return a string and you get text/plain. Return an object and you get JSON, with property names in camelCase (Title becomes "title").
  • TypedResults set the status code. Declaring the return type as Results<Ok<Book>, NotFound> lists every outcome in the signature. In Lesson 2 you will see why: the OpenAPI generator reads it.
  • builder.Services.AddProblemDetails() with UseExceptionHandler() turns errors into one standard JSON shape (RFC 9457) instead of an HTML page or a stack trace. Lesson 3 builds on this.

Cheat sheet

SymptomLikely cause
404 on a route you mappedWrong method (GET vs POST), a route constraint did not match, or a group prefix you forgot.
400 "Failed to read parameter"A required query value is missing, or the body is not valid JSON for the type.
415 Unsupported Media TypeThe POST is missing Content-Type: application/json.
"Unable to resolve service"You forgot to register it in builder.Services.
Data disappears between requestsThe store is scoped or transient. Make it a singleton.
Config value is not what you setA later source overrides it: environment file, env var, or the wrong environment.
