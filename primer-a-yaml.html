YAML in 45 minutes

An OpenAPI file is almost always YAML. YAML is JSON with fewer brackets and quotes, and with whitespace doing the structural work. Learn its few rules and its handful of traps, and Lesson 1 becomes a lesson about APIs instead of about indentation.

The red 1.1 is the most common YAML bug in API specs: version: 1.10 is a number, and the trailing zero is gone. Quote it.

What you will learn

  • The three building blocks: mappings, sequences, scalars.
  • How indentation creates structure, and why tabs break it.
  • When a value needs quotes, and what happens if you forget.
  • Multi-line strings with | and >.
  • The YAML you will meet in OpenAPI files: $ref, status codes, flow style.

1. Three building blocks

Everything in YAML is one of three things. They map exactly onto JSON.

YAMLJSONLooks like
Mappingobjectkey: value lines at the same indent
Sequencearraylines starting with -
Scalarstring, number, boolean, nulla single value
# a mapping (the whole document is one)
title: Library API        # key, colon, SPACE, value
maxPageSize: 100

# a sequence of scalars
owners:
  - alice
  - bob

# a sequence of mappings: each "- " starts a new item
servers:
  - url: https://api.example.com
    description: Production   # same indent as "url" = same item
  - url: http://localhost:5000
    description: Local

The space after the colon matters. key:value is a single string, not a key and a value. The space after the dash matters too.

2. Indentation is the structure

  • Children are indented more than their parent. Siblings line up exactly.
  • Two spaces is the convention. Any number works if you stay consistent within a block.
  • Tabs are forbidden for indentation. Set your editor to insert spaces for .yaml files.
  • A list may sit at the same indent as its key. Both of these are legal and mean the same:
required:          required:
  - id             - id
  - title          - title

3. Scalars and the quoting rules

An unquoted value is guessed: the parser decides whether it is a number, a boolean, null, or a string. Quotes stop the guessing. In YAML 1.2 (what modern parsers use) the guesses are:

You writeYou getIf you meant a string
42, -7integer'42'
1.10, 2.0, 1e3number (1.1, 2, 1000)'1.10'
0123integer 123 (zero lost)'0123'
true, falseboolean'true'
null, ~, nothingnull'null'
yes, no, on, offstring in YAML 1.2, boolean in old 1.1 parsersquote it, or use true/false
2026-01-15string, or a timestamp in some parsers'2026-01-15'
The "Norway problem" In YAML 1.1, country: NO is the boolean false. YAML 1.2 fixed that, but plenty of tools still use 1.1 parsers. Quote anything that could be mistaken for a boolean.

Single or double quotes?

a: 'single: no escapes, write '' for a quote'
b: "double: escapes work\n\té"
c: plain text is fine too, unless it contains ": " or " #"

You must quote a value that:

  • contains ": " (colon + space). The parser reads it as a new key.
  • contains " #" (space + hash). The rest of the line becomes a comment.
  • starts with one of { [ * & ! | > ' " % @ ` or #.

4. Multi-line strings

description: |      # literal: keeps every line break
  Returns all books.
  Sorted by title.
# -> "Returns all books.\nSorted by title.\n"

summary: >          # folded: joins lines with spaces, blank line = paragraph
  Returns all books,
  sorted by title.
# -> "Returns all books, sorted by title.\n"

note: |-            # add "-" to drop the final newline
  No trailing newline.

OpenAPI description fields support Markdown, so | is the usual choice there.

5. Flow style: JSON inside YAML

Brackets and braces work in YAML too. Any JSON is valid YAML. Use flow style for short things only.

tags: [Books, Admin]
id: {type: integer, format: int64}

6. Comments, documents, anchors

# a comment runs to the end of the line
---                 # starts a new document (several per file are allowed)
defaults: &page     # &name sets an anchor
  limit: 20
  offset: 0
search:
  paging: *page     # *name reuses it (an alias)

OpenAPI tools handle anchors unevenly. In specs, use $ref for reuse instead (Lesson 1).

7. YAML you will see in OpenAPI files

paths:
  /books/{id}:                    # keys can contain / and { }
    get:
      responses:
        '200':                    # OpenAPI asks for quoted status codes
          description: OK
          content:
            application/json:     # "/" in a key is fine
              schema:
                $ref: '#/components/schemas/Book'   # MUST be quoted: " #" starts a comment
The $ref trap $ref: #/components/schemas/Book parses without an error. The value is empty, because everything after # is a comment. Your tools will then complain about a null reference somewhere far away. Always quote $ref values.

Cheat sheet

SymptomLikely cause
"mapping values are not allowed here"An unquoted ": " inside a value, or a missing space after a key's colon on the line above.
"found character that cannot start any token" / tab errorA tab in the indentation.
A value is unexpectedly nullAn unquoted # after a space, or an empty value.
A version or ID lost digitsIt was parsed as a number. Quote it.
